PROJETOS DE ISAAC DE CASTRO SILVA


Theodor AI

Theodor AI é uma inteligência artificial desenvolvida por Isaac e integrada ao seu portfólio.

O sistema permite que visitantes conversem com uma IA capaz de responder perguntas sobre Isaac, incluindo sua experiência profissional, projetos, tecnologias, formação e informações pessoais disponibilizadas por ele.

O Theodor AI utiliza recuperação semântica de conhecimento, memória de conversa e modelos de linguagem para produzir respostas contextualizadas.

RAG, memória, embeddings, persistência, Gemini, Groq e a interface em React são componentes internos da arquitetura do Theodor AI e não projetos separados.


COMPONENTES DO Theodor AI

Todos os itens descritos abaixo fazem parte do mesmo Theodor AI.
Eles não são projetos independentes.


Backend do Theodor AI:
- Java.
- Spring Boot.
- API REST.


Inteligência Artificial do Theodor AI:
- Integração com modelos de linguagem.
- Groq como provedor principal das respostas, por ser mais rápido.
- Gemini como fallback caso o Groq esteja indisponível.
- Gemini também é usado para gerar os embeddings da base de conhecimento.


RAG do Theodor AI:
- O RAG é um componente interno do Theodor AI e não um projeto separado.
- Base de conhecimento própria sobre Isaac.
- Divisão da base em chunks.
- Geração de embeddings.
- Busca semântica.
- Similaridade de cosseno.
- Recuperação de trechos relevantes antes da geração da resposta.
- Uso das informações recuperadas como fonte factual para geração das respostas.
- Regras de grounding para reduzir respostas não sustentadas pela base de conhecimento.


Memória conversacional do Theodor AI:
- A memória conversacional é um componente interno do Theodor AI e não um projeto separado.
- Identificação das conversas através de conversationId.
- Persistência do histórico das conversas em banco de dados.
- Armazenamento das mensagens do usuário e das respostas da IA.
- Recuperação automática do histórico persistido após reinicialização da aplicação.
- Uso de uma janela recente do histórico em memória RAM para fornecer contexto à IA.
- Uso das perguntas anteriores do usuário como contexto auxiliar para o RAG.
- Compactação do histórico para controlar o tamanho do contexto enviado ao modelo.
- Persistência do resumo da conversa.
- Persistência da categoria ativa da conversa.


Persistência do Theodor AI:
- A camada de persistência das conversas está implementada.
- O projeto utiliza JPA/Hibernate para persistência.
- Em produção, o banco de dados é PostgreSQL, hospedado no Neon.
- No ambiente de desenvolvimento local, o banco de dados é H2.
- As conversas e mensagens são armazenadas de forma persistente.
- O histórico pode ser recuperado mesmo após a aplicação ser reiniciada.
- A memória conversacional também possui informações persistentes.
- SQL Server não faz parte da implementação do Theodor AI.


Frontend do Theodor AI:
- O frontend é desenvolvido com React e Vite.
- A interface é o próprio portfólio de Isaac, com o chat do Theodor AI integrado.
- O frontend realiza requisições para a API REST do backend em Spring Boot.
- As mensagens enviadas pelo usuário no frontend são processadas pelo backend e as respostas da IA são exibidas na interface.
- O visual usa uma identidade em pixel art, com modo claro e escuro.


Publicação do Theodor AI:
- O portfólio com o Theodor AI está publicado na internet.
- Endereço do portfólio: https://about-me-seven-lovat.vercel.app
- O frontend está hospedado na Vercel.
- O backend roda em um contêiner Docker hospedado no Render.
- O banco de dados PostgreSQL está hospedado no Neon.
- A API possui limite de perguntas por minuto e validação do tamanho das perguntas para evitar uso abusivo.
- Código-fonte: https://github.com/IsaacCastrooSilva/About-me

DESK-FRIENDS
==================================================

Tipo: Projeto pessoal.

Desk-Friends é o projeto mais recente de Isaac e está em desenvolvimento.

Repositório do Desk-Friends: https://github.com/IsaacCastrooSilva/Desk-Friends

O Desk-Friends é um display de mesa que mostra os agentes do Claude Code como invasores em pixel art. O Claude Code é uma ferramenta de programação com inteligência artificial da Anthropic, e cada sessão aberta dela funciona como um agente.

No código, o Desk-Friends aparece com o nome provisório Agents Deck.

Funcionamento do Desk-Friends:
- Hooks do Claude Code enviam o status de cada sessão para um pequeno servidor.
- Um painel com tela sensível ao toque mostra quais agentes estão trabalhando, quais estão esperando uma resposta do usuário e quais estão ociosos.
- Cada agente aparece no painel como um invasor em pixel art, com o nome do projeto em que está trabalhando e há quanto tempo está naquele estado.
- Os agentes que precisam de atenção aparecem primeiro no painel.
- O painel atualiza sozinho, em tempo real.
- O painel roda em um Raspberry Pi, em um celular antigo ou em qualquer navegador.

Funcionalidades do Desk-Friends:
- Ao tocar em um agente, é possível escolher o chapéu e a cor do invasor. A escolha fica salva para cada projeto.
- Sessões sem atividade por 6 horas são removidas automaticamente.
- No Raspberry Pi, o painel pode abrir sozinho em tela cheia (modo quiosque) quando o aparelho liga.
- Possui um modo de demonstração que envia agentes fictícios para mostrar o painel funcionando.

Status dos agentes no Desk-Friends:
- Trabalhando: quando o usuário envia uma pergunta ou o agente usa uma ferramenta.
- Precisa de você: quando o Claude Code envia uma notificação pedindo atenção.
- Ocioso: quando a sessão começa ou o agente termina a tarefa.
- A sessão some do painel quando é encerrada.

Tecnologias do Desk-Friends:
- Node.js 18 ou superior no servidor.
- O servidor não usa nenhuma dependência externa, apenas o módulo HTTP nativo do Node.js.
- Server-Sent Events (SSE) para enviar o estado dos agentes ao painel em tempo real.
- API HTTP própria para receber os eventos dos hooks, salvar a aparência dos agentes e limpar o painel.
- HTML, CSS e JavaScript puros no painel, sem frameworks.
- Canvas 2D para desenhar os invasores em pixel art de 16 por 16 pixels.
- Hooks do Claude Code com um script em Bash que usa curl para enviar os eventos.
- Arquivo JSON para guardar o estado dos agentes e a aparência escolhida para cada projeto.
- Chromium em modo quiosque no Raspberry Pi.

Objetivo do Desk-Friends:
- Permitir acompanhar, com uma olhada rápida na mesa, o que cada agente de IA está fazendo, sem precisar abrir cada sessão.
- Avisar quando algum agente está parado esperando uma resposta.

Desk-Friends não faz parte do Theodor AI. São projetos diferentes.
